# Как настроить и запустить бота

Бот работает на компьютере, пока открыт и запущен Python. Закрыли окно или
выключили компьютер - бот остановился. После включения запустите его снова.

## 1. Подготовьте папку

Скопируйте папку проекта на компьютер, где будет работать бот. Например,
`C:/GiftBot` в Windows или `/Users/anna/Documents/GiftBot` на macOS.
В ней должны находиться `bot.py`, `settings.py`, `requirements.txt`
и `create_example.py`, а также `greeting.txt` с поздравлением и `greeting.png` с открыткой.
Не переносите готовую папку `.venv` с другого компьютера.

Установите Python 3.9 или новее. В Windows при установке включите пункт
`Add Python to PATH`. Если Python уже установлен, повторно устанавливать его
не требуется.

## 2. Откройте окно для команд

Windows: откройте папку бота в Проводнике. В адресной строке окна вместо пути
напишите `cmd` и нажмите Enter. Откроется окно команд в нужной папке.

macOS: откройте приложение «Терминал». Напишите `cd ` с пробелом,
перетащите папку бота в окно терминала и нажмите Enter.

Далее вводите команды по одной строке и нажимайте Enter после каждой.

Windows:

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Эти две команды нужны при первой установке. Нужен доступ к серверу пакетов
Python. При ошибке сертификата или сети попросите ИТ-администратора помочь
с корпоративным доступом; не отключайте проверку TLS.

В командах ниже показан Windows. На macOS заменяйте
`.venv\Scripts\python.exe` на `.venv/bin/python`.

## 3. Подготовьте таблицу сертификатов

Готовый файл уже включён в корень репозитория, рядом с `greeting.txt`:
[скачать certificates.xlsx](certificates.xlsx).
На странице файла GitHub нажмите **Download raw file** (кнопка скачивания).
Сохраните его в папку с `bot.py`. Если скачали весь репозиторий, файл уже
находится в нужной папке. Переименовывать его не требуется.

Если файла нет, создайте пустую таблицу с заголовками командой:

```bat
.venv\Scripts\python.exe create_example.py
```

Откройте `certificates.xlsx` в Excel и заполните данные со второй строки.
Заголовки и комментарии в первой строке показывают обязательные поля.
Сохраните файл с тем же именем и закройте Excel. Пустая таблица никому
не отправляет сообщений. Заполненную таблицу не публикуйте на GitHub.
Лист можно назвать как угодно, например «Подарки» или «Лист1».
Заголовки столбцов должны оставаться такими, как в таблице ниже.
Бот автоматически найдёт лист с `user_login` и `certificate_text`
в первой строке. В файле должна быть только одна такая таблица.
Другие листы без этих заголовков допустимы. Если подходят несколько листов,
бот остановится до отправки: оставьте одну рабочую таблицу сертификатов.

| Столбец | Обязательный | Что вписать |
|---|---|---|
| user_login | Да | Полный корпоративный адрес получателя, например anna@company.ru. Проверьте его особенно внимательно |
| full_name | Нет | Фамилия, имя и отчество, если оно есть. Можно оставить пустым |
| certificate_text | Да | Весь текст персонального сертификата, включая код и пояснение |

Одна строка - один сертификат. Несколько сертификатов одному человеку -
несколько строк с одинаковым `user_login` и разными текстами сертификатов.
Одинаковые адрес и текст считаются одним сертификатом; повторяющиеся строки
объединяются. Номера заполнять не нужно. Старый столбец `certificate_id`, если
он уже есть, можно оставить - бот его игнорирует.
Регистр букв адреса и пробелы по краям адреса и текста не учитываются.
Изменение текста, включая исправление опечатки внутри него, или адреса
означает новый сертификат и допускает новую автоматическую отправку.
Не используйте формулы в обязательных полях. При необходимости задайте
для столбцов формат ячеек «Текстовый». Суммарный текст сертификатов одному
человеку с заголовком сообщения должен укладываться в 6000 символов.

Если таблица рядом с `settings.py`, **менять путь в коде не нужно**.
Если она в другой папке, откройте `settings.py` в Блокноте или другом текстовом
редакторе. Найдите строку:

```python
CERTIFICATES_PATH = "certificates.xlsx"
```

Замените только текст в кавычках полным путём. Пример Windows:

```python
CERTIFICATES_PATH = "C:/GiftBot/Data/certificates.xlsx"
```

Пример macOS:

```python
CERTIFICATES_PATH = "/Users/anna/Documents/GiftBot/Data/certificates.xlsx"
```

Используйте свой путь, а не имя anna из примера. В конце обязательно должно
быть имя файла `.xlsx`. Сохраните `settings.py` и перезапустите бота после
изменения пути. Содержимое самой таблицы он перечитывает без перезапуска.

## 4. Проверьте настройку без отправки

Перед проверкой отредактируйте поздравление:

1. Найдите файл **greeting.txt** рядом с `bot.py`.
2. Откройте его в Блокноте Windows или текстовом редакторе macOS.
3. Замените весь пример своим поздравлением. Можно использовать несколько
   абзацев и подпись компании. Кавычки и Python-код не нужны.
4. Сохраните как обычный текст в кодировке **UTF-8** с тем же именем
   `greeting.txt`. В macOS TextEdit выберите «Формат» - «Сделать обычным текстом».
   Не сохраняйте как Word или RTF и не добавляйте второе расширение `.txt`.

Пример содержимого:

```text
Поздравляем с Новым годом!

Желаем здоровья, радости и успехов!
С наилучшими пожеланиями, ваша команда.
```

Бот добавит поздравление перед заголовком «Ваши сертификаты» и личными
сертификатами. Адреса и коды в поздравление вписывать не нужно: они берутся
из таблицы. Для индивидуального обращения используйте маркеры:

| Маркер в greeting.txt | Что вставляет бот |
|---|---|
| `{first_name}` | Имя получателя |
| `{full_name}` | Всё содержимое full_name |

Например, при `full_name` = `Иванов Иван Петрович` текст в `greeting.txt`:

```text
{full_name}, поздравляем с Новым годом!
```

будет отправлен как:

```text
Иванов Иван Петрович, поздравляем с Новым годом!
```

Для `{full_name}` заполните столбец `full_name` в `certificates.xlsx`.
Если отчества нет, укажите фамилию и имя. Бот вставляет ФИО целиком,
не склоняет его и не заменяет значением столбца `first_name`.


Например, напишите в `greeting.txt`:

```text
{first_name}, поздравляем с Новым годом!

Желаем радости и успехов!
```

В `full_name` укажите **Фамилия Имя Отчество**, например
`Иванова Анна Петровна` - бот вставит `Анна`. Отчество можно опустить;
если указано только одно имя, используется оно. Если ФИО записано в другом
порядке или нужно особое обращение, добавьте в таблицу необязательный столбец
`first_name` и заполните его: он имеет приоритет для `{first_name}`.
Не меняйте порядок ФИО молча - иначе из второго слова может получиться фамилия.

Если маркер требует имя, а оно не заполнено, выдача останавливается с ошибкой.
Для одного адреса все непустые значения имён должны совпадать; имя достаточно
заполнить в одной строке этого получателя. Получатель всегда определяется
по `user_login`. Изменение имени не вызывает автоматическую повторную выдачу.
Без маркеров по-прежнему можно использовать общее поздравление без имён.
После обновления кода один раз перезапустите бот, затем добавьте маркеры
в поздравление. Последующие правки текста перезапуска не требуют.

Суммарная длина поздравления после подстановки имени, заголовка и сертификатов
одного человека ограничена 6000 символами.

Для дальнейшего изменения достаточно сохранить `greeting.txt`: следующая
выдача использует новый текст без перезапуска. Уже отправленные сообщения
не редактируются. Изменение поздравления не запускает повторную рассылку.
При отсутствии, пустом содержимом или неправильной кодировке файла бот
покажет ошибку и не начнёт выдачу. Если файл нужен в другой папке,
измените `GREETING_PATH` в `settings.py`, аналогично пути таблицы.

```bat
.venv\Scripts\python.exe bot.py --check
```

В окне появится запрос **«Вставьте токен бота и нажмите Enter»**.
Вставьте токен, полученный у администратора бота, и нажмите Enter.
Кавычки не нужны. Символы не отображаются - это нормально.
Токен не нужно вставлять в Python-код и нельзя отправлять в переписку.

При правильной настройке появится сообщение «Проверка успешна».
Эта команда проверяет таблицу и доступ к API; сообщения пользователям
не отправляются. Отчёт и база состояния создаются даже в режиме проверки.

## 5. Запустите бота

Открытка находится в `greeting.png` рядом с ботом. При включённой картинке
бот отправляет её и весь текст (персональное поздравление плюс сертификаты)
одним запросом `sendGallery`, а не двумя отдельными сообщениями.
Для другой картинки замените файл или укажите при запуске `--image другой_файл.png`.
Поддерживаются PNG и JPEG; относительный путь считается от папки `bot.py`.
Если указанной картинки нет или её формат неверен, отправка не начинается.

В `settings.py` путь задаётся строкой `GREETING_IMAGE_PATH = "greeting.png"`.
Для работы только с текстом задайте `GREETING_IMAGE_PATH = ""`.
Замена открытки не меняет ключ сертификата и не вызывает повторную рассылку.
Обычный `--check` проверяет файл локально и доступ к API, но не проверяет
принятие одиночного изображения методом sendGallery: для этого нужен тест
реальной отправки одному получателю и визуальное подтверждение в Телемосте.

При потере подтверждения выставляется `unknown`, автоматического повтора
и запасной отправки текста отдельным сообщением не будет. В контракте
sendGallery не описан payload_id; защиту обеспечивает постоянная история SQLite.
Режим одиночной картинки с подписью реализован и протестирован на подставном API;
до массовой отправки обязательно проверьте его на своей тестовой учётной записи.



```bat
.venv\Scripts\python.exe bot.py
```

Снова вставьте токен в скрытый запрос. Для постоянного запуска без ручного
ввода ИТ-администратор может настроить переменную `TELEMOST_BOT_TOKEN`.
После сообщения «Бот запущен» оставьте окно открытым.

При запуске бот СРАЗУ автоматически отправляет новые сертификаты получателям
из таблицы. Писать боту для первой выдачи не требуется. До запуска проверьте
все адреса и тексты. Уже известные отправки со статусами `sent`, `sending`
и `unknown` повторяться не будут. Для проверки без рассылки используйте `--check`.

Если пользователь хочет явно получить свои сертификаты повторно, он может
открыть личный чат с ботом в Телемосте и отправить:

```text
/certificates
```

Бот отправит все сертификаты, закреплённые за корпоративным адресом
этого пользователя. Новый такой запрос разрешает повторную выдачу.
Бот не выдаёт сертификаты другого сотрудника по адресу, написанному в сообщении,
и не отправляет сертификаты в групповые чаты.

Остановка - нажмите Ctrl+C. После повторного запуска история сохранится.

Для запуска только для выбранных получателей добавьте `--only-users`
и их полные корпоративные адреса через пробел. Например:

```bat
.venv\Scripts\python.exe bot.py --organization-id 7835550 --only-users anna@example.org ivan@example.org
```

Укажите свои адреса вместо примеров. Все выбранные получатели должны
присутствовать в таблице, иначе бот остановится до отправки. Остальным
получателям он не отправляет сообщения и не отвечает на их личные запросы.
Уже отправленные и неопределённые попытки не повторяются автоматически.

## 6. Если нужна однократная рассылка по всей таблице

Сначала остановите работающий бот сочетанием Ctrl+C. Проверьте адреса
в таблице. Следующая команда **отправляет реальные сообщения**:

```bat
.venv\Scripts\python.exe bot.py --send-pending
```

Она отправляет только сертификаты, для которых ещё не было попытки выдачи,
и затем завершает работу. Уже отправленные сертификаты автоматически не
повторяются. После завершения можно снова запустить `bot.py` для личных запросов.
Обычный запуск тоже выполняет такую рассылку, затем продолжает работу
с личными запросами. Периодическое расписание не настроено; новые строки,
добавленные во время работы, автоматически рассылаются при следующем запуске.

## 7. Принудительно отправить сертификаты повторно из терминала

Этот режим нужен, если оператор хочет повторить выдачу пользователю,
в том числе после изменения поздравления. Историю очищать не нужно.

1. Если бот уже работает, остановите его Ctrl+C.
2. Проверьте текст `greeting.txt` и данные выбранных получателей в таблице.
3. Выполните команду, заменив адреса примера адресами нужных получателей:

```bat
.venv\Scripts\python.exe bot.py --organization-id 7835550 --resend --only-users anna@example.org ivan@example.org
```

На macOS вместо `.venv\Scripts\python.exe` используйте `.venv/bin/python`.
Для другой организации замените её ID. Введите токен в скрытый запрос.
Бот покажет адреса и количество сертификатов. **Проверьте список**, затем
для реальной отправки напишите **ОТПРАВИТЬ** заглавными русскими буквами
и нажмите Enter. Любой другой ответ, пустая строка или конец ввода отменяют
действие без отправки.

Бот отправит текущее поздравление и все сертификаты выбранных пользователей,
даже если раньше был статус `sent` или `unknown`. Поэтому при `unknown`
предварительно проверьте фактическую доставку: оператор явно разрешает повтор.
Остальных пользователей этот режим не затрагивает. Адреса через `--only-users`
обязательны; если хотя бы одного адреса нет в таблице, отправка не начинается.
Сочетать `--resend` с `--check` или `--send-pending` нельзя.

Повтор сохраняется отдельной попыткой `operator_resend` на листе `Attempts`,
предыдущие записи остаются. После выполнения команда завершает работу.
При неизвестном результате бот не повторяет попытку автоматически.
Повторный запуск `--resend` с новым подтверждением означает ещё одну
намеренную выдачу. Для последующей обычной работы снова запустите `bot.py`.

## 8. Где смотреть результат

Рядом с `bot.py` появятся:

| Файл | Назначение |
|---|---|
| delivery_status.xlsx | Отчёт со статусами. Откройте в Excel, но не редактируйте |
| greeting.txt | Поздравление. Этот файл можно редактировать обычным текстовым редактором |
| bot_state.sqlite3 | Постоянная история, по которой бот предотвращает дубли |
| bot_state.sqlite3-wal и bot_state.sqlite3-shm | Вспомогательные файлы истории, могут появляться во время работы |
| bot.lock | Служебная блокировка второго запуска |

В отчёте лист `Certificates` показывает последнее состояние каждого известного
сертификата, лист `Attempts` - все попытки, включая повторные явные запросы.
Время указано в UTC с обозначением `+00:00`; московское время на 3 часа больше.

| Статус | Что означает и что делать |
|---|---|
| pending | Попыток отправки ещё не было |
| sent | API подтвердил отправку. Это не подтверждение прочтения |
| sending | Попытка началась и ещё не завершена |
| unknown | Подтверждения нет. Сообщение могло дойти. Автоматического повтора не будет: нужна проверка администратором |

Отчёт обновляется при запуске, после отправок и во время работы.
Если файл открыт в Excel и не может обновиться, закройте его: бот повторит
сохранение отчёта. Отправку сертификатов из-за ошибки отчёта он не повторяет.

**Не удаляйте и не заменяйте базу истории пустым файлом.** Не запускайте копии
папки на двух компьютерах одновременно. Для переноса или резервной копии
сначала остановите бот, затем копируйте папку вместе с таблицей и базой истории.
При потере истории отсутствие автоматических дублей гарантировать нельзя.
Отчёт не заменяет базу и не используется для восстановления истории автоматически.

Для `unknown` сначала проверьте фактическую доставку в Телемосте. Если сертификат
не дошёл, пользователь может явно запросить его через `/certificates`.
Не меняйте текст ради повторной автоматической отправки и не очищайте базу.
При обновлении версии сохраните `bot_state.sqlite3`: прежняя история
сопоставляется с адресом и текстом автоматически. Для применения новой версии
остановите старый процесс Ctrl+C и запустите бот заново.

## Если что-то не работает

- «Таблица не найдена»: проверьте имя `certificates.xlsx` и путь из сообщения.
- Ошибка строки Excel: исправьте указанную строку, сохраните файл. Не оставляйте
  незаполненные строки с частью данных.
- Удаление строки из таблицы не удаляет историю её предыдущих отправок.
  Повторное добавление того же адреса и текста не вызывает автоматическую
  повторную отправку.
- «Бот уже запущен»: найдите другое окно бота и остановите его Ctrl+C.
- HTTP 401 или 403: попросите администратора проверить токен и права бота.
- Webhook: администратор должен отключить его для этого бота. Программа сама
  настройки организации не меняет.
- Сбой связи: проверьте интернет. Во время работы polling восстанавливается
  автоматически. Если ошибка произошла до сообщения «Бот запущен», устраните
  её и повторите запуск. Незавершённые отправки автоматически не повторяются.
- Сертификат не найден: проверьте, что в таблице полный адрес именно той
  учётной записи, с которой сотрудник пишет боту.

Перед массовой рассылкой проведите проверку на тестовой учётной записи
с вымышленным сертификатом. Пользователь подтвердил успешную работу
в тестовой организации 21 ноября 2026; в другой организации нужна своя проверка.
