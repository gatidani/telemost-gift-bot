# Бот поздравлятор для Телемоста

## Готовый шаблон сертификатов

[Скачать certificates.xlsx](certificates.xlsx)
(на странице файла нажмите Download raw file).

Обязательные столбцы: `user_login` и `certificate_text`. Необязательный
`full_name` содержит ФИО с отчеством, если оно есть. Подсказки также есть
в комментариях заголовков Excel. Готовый файл лежит в корне репозитория рядом
с `bot.py` и `greeting.txt`. Заполните получателей и сертификаты со второй
строки, сохраните и закройте Excel. Переименовывать файл не нужно.
Название листа может быть любым. Заполненную таблицу с реальными данными
не загружайте на GitHub.

## Статус

Реализован бот для поздравления сотрудников с новым годом и предоставления им подарка в виде какого либо сертификата.

Пошаговый запуск для клиента: [CLIENT_GUIDE.md](CLIENT_GUIDE.md).

Параметры подключения и пути к таблице находятся в `settings.py`.

Поздравление редактируется в `greeting.txt` рядом с ботом (обычный текст UTF-8).
Оно добавляется перед сертификатами и перечитывается при каждой выдаче.
Изменение поздравления не меняет ключ сертификата и не вызывает автоматических
дублей. `--check` также проверяет файл поздравления и общую длину сообщений.
Общий лимит 6000 символов включает поздравление, заголовок и сертификаты.

Для ограниченного запуска есть `--only-users address1@example.org address2@example.org`:
выдача и ответы в личных чатах ограничиваются указанными адресами. Если хотя бы
одного из них нет в таблице, запуск останавливается до отправки.

## Принудительная повторная выдача оператором

```sh
.venv/bin/python bot.py --organization-id 7835550 --resend --only-users anna@example.org ivan@example.org
```

Остановите прежний процесс. Замените адреса примера нужными получателями,
введите токен, проверьте показанный список и подтвердите словом `ОТПРАВИТЬ`.
Бот повторно отправит актуальное поздравление и все сертификаты только этим
получателям независимо от прежних статусов, сохранит попытки как
`operator_resend` и завершится. История остаётся неизменной, дополняясь новыми
записями. Без `--only-users` запуск запрещён; `--check`, `--send-pending`
и `--resend` являются взаимоисключающими режимами. Отмена подтверждения
не отправляет сообщений. Неопределённые попытки автоматически не повторяются.
Подробная пошаговая инструкция есть в `CLIENT_GUIDE.md`.

Реализация: Python, SQLite и один процесс с polling. Личность определяется
по полям API, XLSX проверяется целиком. Все закреплённые сертификаты выдаются
одним личным сообщением. Новый явный запрос разрешает повторную выдачу.
Токен передаётся через переменную окружения или скрытый ввод при запуске.

## Настройка для клиента

В `settings.py` есть подсказки и проверка настройки. Для запуска приложения
используйте `bot.py`; полная инструкция есть в `CLIENT_GUIDE.md`.

1. Откройте папку проекта, где лежит `settings.py`.
2. Сохраните свою Excel-таблицу в эту же папку под именем `certificates.xlsx`.
   Имя листа может быть любым. В первой строке укажите заголовки:
   `user_login`, `full_name`, `certificate_text`.
   Далее заполняйте по одному сертификату в строке. `full_name` можно оставить
   пустым. Номера сертификатов заполнять не требуется.
   Бот сам находит лист по обязательным заголовкам `user_login` и
   `certificate_text`. В книге должна быть только одна такая таблица;
   остальные листы без этих заголовков не мешают. При нескольких подходящих
   листах бот остановится до отправки и попросит устранить неоднозначность.
3. Если таблица рядом с `settings.py`, путь менять не нужно. Если она в другой
   папке, откройте `settings.py` в текстовом редакторе, найдите строку
   `CERTIFICATES_PATH = "certificates.xlsx"` и замените текст внутри кавычек
   полным путём к вашей таблице. Примеры есть непосредственно над настройкой.
4. Откройте терминал в папке проекта. При установленном Python 3 выполните
   `python settings.py` (на macOS при необходимости `python3 settings.py`).
5. Когда появится запрос «Вставьте токен бота», вставьте секретный токен,
   полученный у администратора бота, без кавычек и нажмите Enter.
   Символы при вводе не отображаются. Токен не нужно вставлять в исходный код.
   Если таблица не найдена, сначала исправьте указанный путь и повторите запуск.

Проверка сообщает полный путь к найденному файлу и факт получения токена.
Она не проверяет действительность токена, структуру Excel и доступ к Телемосту.
Токен не сохраняется, при следующем запуске проверки его нужно ввести снова.
Для запуска без ручного ввода администратор может настроить переменную
окружения `TELEMOST_BOT_TOKEN`. Приложение вызывает
`load_settings()` из `settings.py` и использует возвращённые токен и путь.

## API и гарантии

Контракт сверён 21 ноября 2026 с официальной документацией:

- [Polling](https://yandex.ru/dev/messenger/doc/ru/api-requests/update-polling)
- [Отправка текста и payload_id](https://yandex.ru/dev/messenger/doc/ru/api-requests/message-send-text)
- [Поля входящего сообщения](https://yandex.ru/dev/messenger/doc/ru/data-types)
- [Информация о боте](https://yandex.ru/dev/messenger/doc/ru/api-requests/bot-info)

Каждая отправка получает постоянный `payload_id`, записанный до сетевого запроса.
Подтверждённые и неопределённые попытки не повторяются автоматически.
История хранится в SQLite с synchronous=FULL, события дедуплицируются
по чату и ID сообщения, offset polling сохраняется после обработки.
Второй процесс в одной папке блокируется ОС. Несколько машин с разными
копиями базы не поддерживаются. При неизвестном результате выбран приоритет
отсутствия дубля; доставка может требовать ручной проверки.

Сертификат определяется автоматически по адресу и тексту. Адрес приводится
к нижнему регистру; пробелы по краям адреса и текста не учитываются. Изменение
самого текста или адреса означает новый сертификат. Одинаковые строки
объединяются. Старый столбец `certificate_id` можно оставить: он игнорируется.
При следующем запуске прежняя история сопоставляется по сохранённым адресу
и хешу текста, исходные записи попыток не изменяются. База остаётся источником
истории, `delivery_status.xlsx` отражает состояния и не управляет отправкой.

## Индивидуальное имя в поздравлении

В `greeting.txt` используйте `{first_name}`, например:
`{first_name}, поздравляем с Новым годом!`. Значение берётся из `full_name`
в порядке **Фамилия Имя Отчество**: второе слово является именем. Отчество
необязательно, единственное слово воспринимается как имя. Для другого порядка
ФИО или особого обращения можно добавить столбец `first_name` - он приоритетен.
Маркер `{full_name}` вставляет всё ФИО. Получатель определяется по `user_login`.

Например, при `full_name` = `Иванов Иван Петрович` текст в `greeting.txt`:

```text
{full_name}, поздравляем с Новым годом!
```

будет отправлен как:

```text
Иванов Иван Петрович, поздравляем с Новым годом!
```

Для `{full_name}` заполните столбец `full_name` в `certificates.xlsx`.
Если отчества нет, укажите фамилию и имя. Бот вставляет ФИО целиком,
не склоняет его и не заменяет значением столбца `first_name`.

Отсутствующее имя при использовании маркера или противоречивые имена для одного
адреса блокируют выдачу до исправления таблицы. Длина проверяется после
подстановки. Имя и поздравление не входят в ключ сертификата и не вызывают
новой автоматической выдачи. Существующий текст greeting.txt не заменяется:
добавьте маркер после обновления и перезапуска кода. Для уже выданных
сертификатов используйте явный запрос или подтверждённый `--resend`.

Реализация: Python, SQLite и один процесс с polling. Личность определяется
по полям API, XLSX проверяется целиком. Все закреплённые сертификаты выдаются
одним личным сообщением. Новый явный запрос разрешает повторную выдачу.
Токен передаётся через переменную окружения или скрытый ввод при запуске.

контрольного испытания. Заказчик должен повторить проверку в своей организации.

## Дальнейшая работа

- Установить зависимости и выполнить полный набор тестов: `python -m unittest -v test_bot`.
- Проверить `bot.py --check` и отправку тестовому пользователю в организации.
- При обычном запуске бот показывает план и после подтверждения отправляет новые сертификаты,
  затем обслуживает личные запросы. `--send-pending` завершает процесс после
  рассылки, `--check` проверяет настройки без отправки. Периодическое расписание
  не настроено.

## Картинка и подпись одним сообщением

При `GREETING_IMAGE_PATH = "greeting.png"` в settings.py бот использует
`messages/sendGallery/`: multipart-поле `images` с одной открыткой и `text`
с персональным поздравлением и всеми сертификатами. На ответ с подтверждёнными
message_id и изображением записывается sent; неоднозначный ответ даёт unknown.
Автоматических повторов или отправки отдельного текста при ошибке нет.
Текстовые служебные ответы остаются sendText. В контракте sendGallery нет
payload_id, поэтому защита от дублей основана на журнале SQLite.

Открытка greeting.png расположена рядом с greeting.txt. Можно выбрать другую
через `--image путь.png` или отключить её пустым GREETING_IMAGE_PATH.
Отсутствующий файл проверяется до отправки; общий лимит текста - 6000 символов
после подстановки ФИО. Новый файл картинки не запускает повтор автоматически.
Документация не указывает минимальное число изображений; одиночную картинку
нужно проверить реальной отправкой на тестовую учётную запись до рассылки.
[Контракт sendGallery](https://yandex.ru/dev/messenger/doc/ru/api-requests/message-send-gallery).

Реализация: Python, SQLite и один процесс с polling. Личность определяется

   листах бот остановится до отправки и попросит устранить неоднозначность.
3. Если таблица рядом с `settings.py`, путь менять не нужно. Если она в другой
   папке, откройте `settings.py` в текстовом редакторе, найдите строку
   `CERTIFICATES_PATH = "certificates.xlsx"` и замените текст внутри кавычек
   полным путём к вашей таблице. Примеры есть непосредственно над настройкой.
4. Откройте терминал в папке проекта. При установленном Python 3 выполните
   `python settings.py` (на macOS при необходимости `python3 settings.py`).
5. Когда появится запрос «Вставьте токен бота», вставьте секретный токен,
   полученный у администратора бота, без кавычек и нажмите Enter.
   Символы при вводе не отображаются. Токен не нужно вставлять в исходный код.
   Если таблица не найдена, сначала исправьте указанный путь и повторите запуск.

Проверка сообщает полный путь к найденному файлу и факт получения токена.
Она не проверяет действительность токена, структуру Excel и доступ к Телемосту.
Токен не сохраняется, при следующем запуске проверки его нужно ввести снова.
Для запуска без ручного ввода администратор может настроить переменную
окружения `TELEMOST_BOT_TOKEN`. Приложение вызывает
`load_settings()` из `settings.py` и использует возвращённые токен и путь.

## API и гарантии

Контракт сверён 21 ноября 2026 с официальной документацией:

- [Polling](https://yandex.ru/dev/messenger/doc/ru/api-requests/update-polling)
- [Отправка текста и payload_id](https://yandex.ru/dev/messenger/doc/ru/api-requests/message-send-text)
- [Поля входящего сообщения](https://yandex.ru/dev/messenger/doc/ru/data-types)
- [Информация о боте](https://yandex.ru/dev/messenger/doc/ru/api-requests/bot-info)

Каждая отправка получает постоянный `payload_id`, записанный до сетевого запроса.
Подтверждённые и неопределённые попытки не повторяются автоматически.
История хранится в SQLite с synchronous=FULL, события дедуплицируются
по чату и ID сообщения, offset polling сохраняется после обработки.
Второй процесс в одной папке блокируется ОС. Несколько машин с разными
копиями базы не поддерживаются. При неизвестном результате выбран приоритет
отсутствия дубля; доставка может требовать ручной проверки.

Сертификат определяется автоматически по адресу и тексту. Адрес приводится
к нижнему регистру; пробелы по краям адреса и текста не учитываются. Изменение
самого текста или адреса означает новый сертификат. Одинаковые строки
объединяются. Старый столбец `certificate_id` можно оставить: он игнорируется.
При следующем запуске прежняя история сопоставляется по сохранённым адресу
и хешу текста, исходные записи попыток не изменяются. База остаётся источником
истории, `delivery_status.xlsx` отражает состояния и не управляет отправкой.

## Проверка токена перед рассылкой

При запуске первым сетевым запросом выполняется GET `self/get`:
проверяется токен и корректный ответ с ID и логином бота. При ошибке
отображается одно понятное сообщение и бот завершает работу до чтения Excel,
создания или восстановления SQLite и отчёта. Токен в вывод не попадает.
Это действует для обычного запуска, `--check`, `--send-pending` и `--resend`.

Если доступ теряется во время работы, при HTTP 401/403/404 или `ok: false`
на запрос сообщений бот перепроверяет `self/get`. При провале проверки
дальнейшая рассылка и polling прекращаются. Текущая незавершённая попытка
остаётся unknown, следующие получатели не получают ошибочных попыток.
Если проверка токена успешна, ошибка относится к конкретному запросу,
а не автоматически ко всему боту. Например, недоступный получатель с 404
не означает сам по себе неверный токен.
[Информация о боте](https://yandex.ru/dev/messenger/doc/ru/api-requests/bot-info).

## Подтверждение запуска и прогресс

По умолчанию в settings.py задано `CONFIRM_BEFORE_SEND = True`.
После проверки токена и загрузки файла бот показывает своё имя, логин и ID,
полный путь к таблице, количество сертификатов после объединения дублей
и получателей. Отдельно указаны новые сертификаты и исключённые по истории.
При `--only-users` сводка относится только к выбранным адресам.

Для начала введите `НАЧАТЬ`. Enter, любой другой ответ или конец ввода
отменяют запуск без отправки сообщений и без обработки личных запросов.
`--check` показывает сводку и завершается без вопроса и без отправки.
`--send-pending` тоже требует подтверждения и завершается после рассылки.
`--resend` всегда требует своего подтверждения `ОТПРАВИТЬ`.

В процессе видны номер получателя `[1/10]`, его статус, число оставшихся
получателей и счётчики сертификатов: отправлено, пропущено по истории,
без подтверждения. В конце выводится итог; подробности - в delivery_status.xlsx.
Неизвестный результат не считается успешной отправкой.

Строки таблицы фиксируются до подтверждения: добавленные во время ожидания
строки не расширяют текущую рассылку. Защита от дублей повторно проверяется
в транзакции перед каждой отправкой.

Для намеренного запуска без оператора замените настройку на
`CONFIRM_BEFORE_SEND = False`. Сводка и прогресс останутся, обычная рассылка
начнётся без вопроса. Подтверждение `--resend` при этом не отключается.
