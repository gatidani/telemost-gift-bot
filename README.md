# Бот поздравлятор для Телемоста

## Статус

Реализована первая версия приложения. Защита от повторов проверена локально.
Пройден 41 тест, включая Excel, совместимость прежней истории,
автоматическую выдачу при запуске и редактируемое поздравление.
21 ноября 2026 пользователь подтвердил успешную работу бота после запуска
автоматической выдачи. Перед внедрением в другую организацию нужна её проверка.

Пошаговый запуск для клиента: [CLIENT_GUIDE.md](CLIENT_GUIDE.md).

Параметры подключения и пути к таблице находятся в `settings.py`.

Поздравление редактируется в `greeting.txt` рядом с ботом (обычный текст UTF-8).
Оно добавляется перед сертификатами и перечитывается при каждой выдаче.
Изменение поздравления не меняет ключ сертификата и не вызывает автоматических
дублей. `--check` также проверяет файл поздравления и общую длину сообщений.
Общий лимит 6000 символов включает поздравление, заголовок и сертификаты.

Для ограниченного запуска есть `--only-users address1@example.org address2@example.org`:
выдача и ответы в личных чатах ограничиваются указанными адресами. Если хотя бы
одного из них нет в таблице, запуск останавливается до отправки.

## Принудительная повторная выдача оператором

```sh
.venv/bin/python bot.py --organization-id 7835550 --resend --only-users anna@example.org ivan@example.org
```

Остановите прежний процесс. Замените адреса примера нужными получателями,
введите токен, проверьте показанный список и подтвердите словом `ОТПРАВИТЬ`.
Бот повторно отправит актуальное поздравление и все сертификаты только этим
получателям независимо от прежних статусов, сохранит попытки как
`operator_resend` и завершится. История остаётся неизменной, дополняясь новыми
записями. Без `--only-users` запуск запрещён; `--check`, `--send-pending`
и `--resend` являются взаимоисключающими режимами. Отмена подтверждения
не отправляет сообщений. Неопределённые попытки автоматически не повторяются.
Подробная пошаговая инструкция есть в `CLIENT_GUIDE.md`.

Реализация: Python, SQLite и один процесс с polling. Личность определяется
по полям API, XLSX проверяется целиком. Все закреплённые сертификаты выдаются
одним личным сообщением. Новый явный запрос разрешает повторную выдачу.
Токен передаётся через переменную окружения или скрытый ввод при запуске.

## Выполненные проверки

13 ноября 2026 пользователь выполнил локальные запросы API и сообщил:

- Получение информации о существующем боте: HTTP 200, webhook отсутствует.
- Первая тестовая отправка: HTTP 200, личный чат; пользователь подтвердил
  появление сообщения в Телемосте. Визуальная проверка всех пяти сертификатов
  отдельно не подтверждена.
- Вторая тестовая отправка: HTTP 200, личный чат; фактическое получение
  отдельно не подтверждено.

Использованы только вымышленные реквизиты. Испытание проводилось на существующем
боте, а не на новом, как первоначально предполагалось. Отсутствие предыдущего
диалога получателя отдельно не подтверждено. Вывод о первом контакте требует
контрольного испытания. Заказчик должен повторить проверку в своей организации.

## Дальнейшая работа

- Установить зависимости и выполнить полный набор тестов: `python -m unittest -v test_bot`.
- Проверить `bot.py --check` и отправку тестовому пользователю в организации.
- При обычном запуске бот автоматически отправляет новые сертификаты,
  затем обслуживает личные запросы. `--send-pending` завершает процесс после
  рассылки, `--check` проверяет настройки без отправки. Периодическое расписание
  не настроено.

## Настройка для клиента

В `settings.py` есть подсказки и проверка настройки. Для запуска приложения
используйте `bot.py`; полная инструкция есть в `CLIENT_GUIDE.md`.

1. Откройте папку проекта, где лежит `settings.py`.
2. Сохраните свою Excel-таблицу в эту же папку под именем `certificates.xlsx`.
   Назовите лист `Certificates`. В первой строке укажите заголовки:
   `user_login`, `full_name`, `certificate_text`.
   Далее заполняйте по одному сертификату в строке. `full_name` можно оставить
   пустым. Номера сертификатов заполнять не требуется.
3. Если таблица рядом с `settings.py`, путь менять не нужно. Если она в другой
   папке, откройте `settings.py` в текстовом редакторе, найдите строку
   `CERTIFICATES_PATH = "certificates.xlsx"` и замените текст внутри кавычек
   полным путём к вашей таблице. Примеры есть непосредственно над настройкой.
4. Откройте терминал в папке проекта. При установленном Python 3 выполните
   `python settings.py` (на macOS при необходимости `python3 settings.py`).
5. Когда появится запрос «Вставьте токен бота», вставьте секретный токен,
   полученный у администратора бота, без кавычек и нажмите Enter.
   Символы при вводе не отображаются. Токен не нужно вставлять в исходный код.
   Если таблица не найдена, сначала исправьте указанный путь и повторите запуск.

Проверка сообщает полный путь к найденному файлу и факт получения токена.
Она не проверяет действительность токена, структуру Excel и доступ к Телемосту.
Токен не сохраняется, при следующем запуске проверки его нужно ввести снова.
Для запуска без ручного ввода администратор может настроить переменную
окружения `TELEMOST_BOT_TOKEN`. Приложение вызывает
`load_settings()` из `settings.py` и использует возвращённые токен и путь.

## API и гарантии

Контракт сверён 21 ноября 2026 с официальной документацией:

- [Polling](https://yandex.ru/dev/messenger/doc/ru/api-requests/update-polling)
- [Отправка текста и payload_id](https://yandex.ru/dev/messenger/doc/ru/api-requests/message-send-text)
- [Поля входящего сообщения](https://yandex.ru/dev/messenger/doc/ru/data-types)
- [Информация о боте](https://yandex.ru/dev/messenger/doc/ru/api-requests/bot-info)

Каждая отправка получает постоянный `payload_id`, записанный до сетевого запроса.
Подтверждённые и неопределённые попытки не повторяются автоматически.
История хранится в SQLite с synchronous=FULL, события дедуплицируются
по чату и ID сообщения, offset polling сохраняется после обработки.
Второй процесс в одной папке блокируется ОС. Несколько машин с разными
копиями базы не поддерживаются. При неизвестном результате выбран приоритет
отсутствия дубля; доставка может требовать ручной проверки.

Сертификат определяется автоматически по адресу и тексту. Адрес приводится
к нижнему регистру; пробелы по краям адреса и текста не учитываются. Изменение
самого текста или адреса означает новый сертификат. Одинаковые строки
объединяются. Старый столбец `certificate_id` можно оставить: он игнорируется.
При следующем запуске прежняя история сопоставляется по сохранённым адресу
и хешу текста, исходные записи попыток не изменяются. База остаётся источником
истории, `delivery_status.xlsx` отражает состояния и не управляет отправкой.
